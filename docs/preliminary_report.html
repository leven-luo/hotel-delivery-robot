Project 5 · Reinforcement Learning and Optimal Control for Autonomous Systems I · November 2026

1. GitHub repository

https://github.com/leven-luo/hotel-delivery-robot (public)

2. Project description

We will test whether jointly controlling vehicle speed and two tray angles can shorten delivery time while keeping a freestanding cup upright and avoiding collisions. The payload is a tall cup of about 330 mL standing freely on a tray that tilts in pitch and roll; the robot delivers it along a known route from the hotel lobby to a guest room. The robot knows where corridors, doorways and intersections are, but it can detect a pedestrian only after the person becomes visible. A separate path follower handles steering along the route; the policy chooses the target speed and the two tray angles.

We want the robot to drive fast in open corridors. Whether it learns to slow down before an occluded doorway, before any pedestrian is seen, is a hypothesis we will test: we deliberately impose no doorway speed limit on the learned policy, since that would decide the outcome in advance. The problem combines optimal control (speed and tray commands jointly determine travel time and tipping risk along the whole route) with reinforcement learning (acting on partial observations of pedestrians).

3. Tools and simulation

Existing code (Python/NumPy, Gymnasium, Stable-Baselines3/PyTorch). Our first simulator (v0) contains a servo model (pure delay, first-order lag, rate and angle limits), chassis tilt from acceleration and bumps, and a route generator with acceleration, braking, turns and speed bumps. It also contains gravity-feedforward tray controllers, a Gymnasium environment, training (SAC/PPO) and evaluation scripts, and unit tests with continuous integration. In v0, the whole trip is generated in advance from a prescribed speed profile, so the controller cannot change when the robot arrives anywhere.

Planned closed loop (to be added). At every control step the policy outputs a target speed. The vehicle model updates the actual speed within acceleration and deceleration limits, and the actual speed updates the position along the route. From this position the simulator computes the distance to the next doorway, whether a pedestrian is visible, whether a collision occurs, and when the cup is delivered. Two policies that start from the same point therefore diverge: the one that brakes earlier reaches the doorway later and also subjects the cup to different accelerations. The first scenario is one corridor with one blind doorway, where a pedestrian may step out with a set probability. The cup on the tray is modeled with a simplified tipping/sliding criterion based on the tray-frame specific force. Matplotlib will be used for result plots.

Hardware (planned). An IMU, a battery and a wireless module will be fixed inside the cup, and a second IMU on the tray, so that the cup can slide or fall freely. All trials will use the same cup, load and electronics placement. Chassis and servo models (candidates: Waveshare UGV02, DS3218) and the purchase status are being confirmed by the hardware lead.

4. Control algorithms and tip-over determination

  • Reference controllers. A preset speed profile with either a fixed tray or a gravity-feedforward tray. The feedforward tilts the tray to θ* = atan2(a, g + az) per axis to align the cup with g − a; in v0 it can also preview the planned horizontal acceleration commands to compensate servo lag.
  • Learning method: SAC (Soft Actor-Critic). It learns continuous commands for target speed, tray pitch and tray roll. Its observation contains the actual speed, measurable attitude (chassis and tray IMUs), the distance to the next doorway, and only the pedestrian information that the sensors can currently see; it receives nothing about pedestrians who are not yet visible.
  • Events and reward. Every episode records a tip label (0 = not tipped, 1 = tipped), the time of the first confirmed tip, collisions and the delivery time. If the tray is deliberately tilted and the cup stays upright, this counts as not tipped. The reward is a cost for each elapsed time step, a bonus on successful delivery, and a failure penalty applied at the step where a tip-over or collision is recorded, which also ends the episode. In simulation, if only the quasi-static criterion is implemented, the corresponding results will be reported as "risk threshold exceeded" rather than as tip-overs.
  • Tip-over detection on hardware. Tipping is judged from the angle between the cup axis and the tray normal and how long it persists. The threshold and duration are calibrated on manually labeled real tip-overs and on recordings where the cup recovers after a bump.
  • Safety rule. All methods share the same external emergency-brake rule for a visible pedestrian, so differences come from the policies, not from the safety layer.
  • Extensions if time permits. An MPC baseline that slows down or stops for pedestrians it has already seen, using the same emergency brake, and a second learning algorithm (PPO). The core simulation below has priority.

5. Planned experiments and expected results

Experiment 1: tray control at a preset speed. Under the same braking, turning and bump conditions, we compare the number of tip-overs (in simulation: risk-threshold exceedances) with a fixed tray and with the feedforward tray. Hardware trials follow if the platform is ready.

Experiment 2 (core simulation): delivery through one corridor with one blind doorway.

All groups use the same held-out routes, pedestrian event settings, visible information, control limits and external braking rule. For each group we report the number of trials, success rate, tip-over rate, collision rate and the delivery time of successful episodes, and compare time only at similar risk. In addition, on held-out trials with no pedestrian, we will compare approach speeds at a blind doorway and on a matched open corridor segment with similar curvature and surface; this tests whether the robot slows down before it receives any pedestrian observation, rather than only braking after seeing someone.

Hypotheses. Joint control will reduce delivery time at comparable tip-over and collision rates; the learned policy will slow down near blind doorways while keeping higher speeds in open corridors.
